# Tool/V2 资产扩充与目录指南

核对版本：2026-09-27，女性角色接入后的 Tool/V2（22 套男性／外星人服装、10 套女性服装、200 模块）。

### 面部纹样改为贴图（2026-09-27）

纹样贴图放在 `UnityProject/Assets/AstraToolV2/Resources/FaceMarks/`，人类使用 `Human_01.png` 至 `Human_05.png`，灰裔外星人使用 `Alien_01.png` 至 `Alien_05.png`；编号 0 表示无。黑色为无纹样、白色为有纹样，颜色由角色的强调色控制。贴图采用专用 UV2，叠加在头部皮肤材质上，不再创建 `Mark_*` 网格。

`Tools/face_details.py` 负责从代码生成现有纹样遮罩、头部 UV2 与实体面罩。调整现有图案可以修改该脚本并重建模型；直接编辑 PNG 后不要再执行模型重建，否则生成步骤会覆盖它。UV2 映射为 Blender 模型坐标 `u=(x+0.20)/0.40`、`v=(z-1.55)/0.40`，非正面皮肤区域使用遮罩外坐标；可根据原 PNG 的位置修改图案。特殊解剖头型仍使用自身配色，未开放这些通用颊纹。

新增纹样编号时，同步扩充 `ToolCreatorOptions.Marks`、`Normalize` 中的纹样编号范围，并提供两种族对应 PNG。`ToolCharacterView.FaceMark` 按编号从 Resources 读取；`ToolFaceTextureImport` 设定线性遮罩、Clamp 和无压缩导入。材质混色在 `Shaders/Character.shader` 的 `_FaceMarkTex / _FaceMarkColor` 中完成。动作骨架与脸型形态键不变。

**项目根目录：`F:\Documents\GitHub\GameDev_Performance_System\Tool\V2`**

本文中的相对路径均从这个目录开始；`U/` 是 `UnityProject/Assets/AstraToolV2/` 的缩写。文档区分“已经存在的目录”和“新增资产时建议创建的目录”，后者不是已经实现的自动导入功能。

## 1. 先看这一页：新增资产放哪里

**当前工具不会扫描文件夹并自动增加捏人选项。** 新衣服、发型要经历“保存源文件 → Blender 接入共享模型 → 注册编号和菜单 → Unity 重建 → 检查”五步。只把 FBX 拖进 Unity，选项不会自动出现。

| 你要增加的内容 | 原始资源放哪里 | 修改后的源文件建议放哪里 | 接入位置 |
| --- | --- | --- | --- |
| 下载的整套资源包 | **已有** `Source/Downloads/<资源包名>/`；压缩包也放在 Downloads | 不直接覆盖下载原件 | 同目录保留许可证，在 `THIRD_PARTY_NOTICES.md` 登记来源 |
| 人类发型、帽子 | `Source/Downloads/<资源包名>/` | **建议新建** `Source/Custom/Hair/<资产名>/` | `Tools/build_modular.py`；指定 Quaternius 基础角色包的发型另见 `Tools/import_ubc_hair.py` |
| 衣服、裤子、鞋靴 | `Source/Downloads/<资源包名>/` | **建议新建** `Source/Custom/Clothing/<资产名>/` | `Tools/build_modular.py` 的原有 `outfits`；新增太空服在 `Tools/space_outfits.py` |
| 外星人颅冠 | 下载原件同上；自制可以没有下载目录 | **建议新建** `Source/Custom/Crests/<资产名>/` | 当前程序化颅冠在 `Tools/alien_design.py`；手工模型需增加导入逻辑 |
| 眼镜、面罩、护颈 | 下载原件同上 | **建议新建** `Source/Custom/FaceAccessories/<资产名>/` | `Tools/build_modular.py` 的 `FaceAcc_` 模块部分 |
| 背包、腰包、护肩等装备 | 下载原件同上 | **建议新建** `Source/Custom/Gear/<资产名>/` | `Tools/build_modular.py` 的 `Gear_` 模块部分 |
| 外星人新头型 | 下载原件同上 | **建议新建** `Source/Custom/Heads/<资产名>/` | `Tools/alien_design.py`，以及头型能力、适配参数和范围注册 |
| 仅增加颜色 | 不需要模型文件 | 不需要 | `U/Runtime/ToolCreatorOptions.cs` 中相应颜色数组 |
| 动作动画 | 原始包放 Downloads | 如需编辑，可建 `Source/Custom/Animations/<资产名>/` | Unity 动画文件放 `U/Animations/`，再注册动作目录与菜单；见第 7 节 |
| 用已有选项捏一个新角色 | 不需要增加原始资源 | 不需要 | 在 Unity 捏人窗口保存，工具生成 `U/Characters/*.asset` 与 `U/Characters/Prefabs/*.prefab` |

建议一个新增资产一个目录，例如以下目录在真正添加资源时再创建：

```text
Source/Custom/
├─ Hair/Hair_Human_33_SideBraid/
│  ├─ Source.blend          可编辑模型
│  ├─ Source.fbx            需要脚本导入时提供
│  ├─ Preview.png           正侧背面参考
│  └─ README.md             来源、目标 ID、比例、绑定、修改记录
└─ Clothing/Outfit_22_LabCoat/
   ├─ Source.blend          上衣、裤子、鞋分开的对象
   ├─ Source.fbx
   ├─ Preview.png
   └─ README.md
```

**Source/Custom 只是推荐的源文件组织方式，当前尚无通用文件夹扫描器。** 开发接入时需要在构建脚本中明确加载这些路径。

## 3. 模块名称、菜单与保存编号

保存文件使用数字 ID，而运行时通过对象名选中模块。**对象名、数字 ID 和菜单数组下标必须对应。** 新项目应先检查最新代码，再使用下表中的“下一个 ID”；本文只是当前版本快照。

| 类型 | Blender 导出对象名 | 当前编号 | 下一个可追加 ID | 菜单注册 |
| --- | --- | --- | --- | --- |
| 人类发型 / 帽饰 | `Hair_Human_33` 等 | 0–32；0 为无发，无需空网格 | 33 | `HumanHair`、`HumanHairGroups` |
| 外星人颅冠 | `Hair_Alien_12` 等 | 0–11；0 为无冠 | 12 | `AlienHair`、`AlienHairGroups` |
| 上衣 | `Body_32` 等 | 0–31；22–31 为女性，0 是实际航行服 | 32 | `Outfits`、`OutfitGroups` |
| 裤子 | `Legs_32` 等 | 0–31；22–31 为女性 | 32 | `Outfits`、`OutfitGroups` |
| 鞋靴 | `Feet_32` 等 | 0–31；22–31 为女性 | 32 | `Outfits`、`OutfitGroups` |
| 人类 / 外星人面饰 | `FaceAcc_Human_10` / `FaceAcc_Alien_10` | 0–9；0 为无 | 10 | `FaceAccessories` 与兼容白名单 |
| 身体装备 | `Gear_10` | 0–9；0 为无 | 10 | `GearAccessories` |
| 面部纹样 | `Mark_Human_06` / `Mark_Alien_06` | 0–5；0 为无 | 6 | `Marks` |
| 外星人头型 | 0 为 `Head_Alien`，其余 `Head_Alien_01` 等 | 0–9 | 10，需扩充多处范围 | `AlienFaces`、头型能力、颅冠适配 |

名称中的数字目前使用至少两位格式（例如 `03`、`10`、`33`）。没有名称后缀的 `Head_Alien` 是 0 号头的特例。

### 需要修改的代码

| 文件 / 符号 | 负责什么 | 新增时要留意 |
| --- | --- | --- |
| `U/Runtime/ToolCreatorOptions.cs` | 选项名、分类、颜色、范围限制、随机生成 | 数组决定显示名称；`HumanHairGroups` / `AlienHairGroups` 决定层级位置 |
| 同文件 `Normalize()` | 防止配方数据越界 | 发型和衣服已按数组长度限制；面饰、装备、纹样、脸型等仍有固定上限 |
| 同文件 `FaceAccessoryIds()` / `Exotic()` / `HasBrows()` | 不同外星人头型的可选能力 | 新面饰不能只加显示名，还要适配网格并加入允许列表 |
| `U/Runtime/ToolCharacterView.cs` | 依据名称启用网格、设置形态键和颜色 | 沿用既有命名的普通新发型 / 衣服通常不用增加选择分支；新模块类别、例外或材质语义需要改 |
| `U/Runtime/ToolWorkbench.cs` | 独立程序的菜单和预览 | 使用共用选项表；新类别、更多层级或额外控制需要修改这里 |
| `U/Editor/ToolV2CharacterCreatorWindow.cs` | Unity 编辑器中的捏人界面 | 与运行版同步新增分类和布局；不要只改一端 |
| `U/Editor/ToolV2CreatorBuild.cs` | 初始资源目录、保存角色、重建 Prefab | `CreateCatalog()` 已有目录时直接返回，不会自动补新材质 / 动画 |
| `U/Editor/ToolV2QA.cs` | 模块、姿势、范围和保存检查 | 发型与混搭服装编号随数组长度增长；`ToolOutfitRuntimeQA` 从 ID 10 遍历新增服装；纹样 `%6` 等仍固定 |

保持已有 ID 的含义，不在数组中间插入新选项，也不要为了排序重排数组。需要调整菜单显示顺序时改分组 ID 列表。发型 10 是短寸、11 是航行头盔，现有逻辑和回归检查依赖这两个编号。

当前菜单是“一级类别 → 子类别 → 样式”。同一个发型 ID 必须恰好出现在一个发型分组里，不能遗漏或重复；分组顺序可以变化。服装现为“装扮 → 部位 → 用途分类 → 样式”，使用 `OutfitCategories` / `OutfitGroups`；每个服装 ID 也必须恰好属于一组。

## 4. 示例一：增加人类发型 33

1. **放源文件。** 下载原件保存到 `Source/Downloads/<包名>/`，修改后的模型另存为 `Source/Custom/Hair/Hair_Human_33_SideBraid/Source.blend`，需要 FBX 导入时同目录保存 `Source.fbx`。登记许可证和来源。
2. **按现有头部适配。** 检查比例、朝向、发际线、耳部和后脑。短发要保持连续头皮覆盖；长发用实体发束，避免一片圆弧或穿入肩膀的发片。网格绑定到共享 `Head` 骨骼。
3. **接入 Blender 构建。** 在 `build_modular.py` 的统一 `for o in made:` 形态键处理之前导入，并将对象命名为 `Hair_Human_33`。纳入 `made`，绑定当前 `rig`，使用 `M['Hair']` 对应的 `Q_Hair` 材质。导入带来的额外骨架应在重新绑定后移除。
4. **保留统一适配。** `Hair_` 前缀会让总脚本为它生成 `Face01–09`、`WidthWide / WidthNarrow`、`JawWide / JawNarrow` 等键。若导入网格已经带形态键，要明确保留、重建或映射策略，避免生成 `Basis.001`、重复键或错误拓扑。
5. **注册显示名。** 在 `ToolCreatorOptions.HumanHair` 尾部追加“侧编发”，它自然成为数组下标 33。把 `33` 加入 `HumanHairGroups` 的“长发束发”组；不需要把 33 插入旧数组中间。
6. **重建并检查。** 依第 8 节重建。确认 `modular_manifest.json` 有 `Hair_Human_33`、两端菜单都能选中、换脸宽不露头皮、保存载入后仍是 33。

如果新增资源来自当前 Universal Base Characters 包，可参考 `import_ubc_hair.py` 的 `ubc_sources` 映射和处理方式。该脚本已有特定来源的朝向、尺寸、女性头部偏移及长发长度调整，**不是任意 FBX 通用导入器**；换来源时不能原样套用数值。现有 ID 22 / 23 来自同一个 `Hair_Long.fbx` 的两个长度适配，27 / 30 / 31 / 32 对应其余原包发型。

新增独立导入脚本时，例如 `Tools/import_custom_assets.py`，还必须在主脚本的统一形态键阶段之前明确调用；仅创建文件不会执行。不要把每款发型分别放进 `U/Models/` 后期待运行时自行拼装：当前 `ToolCharacterView` 只遍历共享模型内已有的模块。

## 5. 示例二：增加第 23 套服装（ID 22）

当前 UI 虽然可以分别选择上衣、裤子和鞋，但三者**共用同一个 `Outfits` 选项数组**。按现有架构追加一个服装名称，需要让这个 ID 的三个部件都有效。

1. 将新服装源文件放到 `Source/Custom/Clothing/Outfit_22_LabCoat/`。
2. 准备 `Body_32`、`Legs_32`、`Feet_32` 三个对象。若只做了新上衣，可以为 32 号裤子和鞋复用已有网格的副本；如果希望上衣、裤子、鞋的数量完全独立，则需要先拆分选项表、范围限制、随机逻辑和 UI。
3. 将服装蒙皮转移 / 调整到现有共享骨架。上衣需要跟随胸、肩、手臂，裤子需要跟随髋、腿，鞋跟随足部；不要把整件衣服都绑定到 Head 或 Hips。对齐领口、腰线、袖口与裸露皮肤的连接边界。
4. 接入 `Tools/space_outfits.py`：在 `SPACE_OUTFITS` 追加显式编号 32 的源件映射，并添加造型处理；或者增加一个在统一形态键之前执行的导入脚本。**不要继续在主脚本的旧 `outfits` 数组尾部追加，它只负责 0–9，会与太空服 10–21、女性服装 22–31 冲突。** 外部 FBX / Blend 必须先导入并注册；`duplicate()` 查找的是主脚本起始时建立的 `source` 字典，写入不存在的对象名会报错。
5. 在统一形态键处理前完成 Mirror 等必要修改器烘焙。`Body_`、`Legs_`、`Feet_` 模块会生成 `Body01–07` 体型键，保持同体型下的连接一致。
6. 在 `ToolCreatorOptions.Outfits` 尾部追加“实验服”，并把 ID 32 加入一个 `OutfitGroups` 或 `FemaleOutfitGroups` 分组。`Normalize()` 按当前底模所属的服装分组校验合法 ID，新增服装必须同时加入相应分组；可为新增服装追加 `SpaceSuitColors` / `SpaceAccentColors`，未配置时使用普通色板的回退颜色。
7. 更新验证：`ToolOutfitRuntimeQA` 已遍历 ID 10 至 `Outfits.Length - 1`，核对三个模块并播放所有 42 个动作。仍需更新服装名称联系表脚本，以及新衣服的边界 / 材质等特定检查。`SeedStarterCast()` 中的 `%10` 只决定初始预设分布，不是正式注册；已有预设也不会自动换装。
8. 重建并检查待机、说话、坐下、跪姿维修、抬手、转身。特别查看腋下、肩膀、肘、裆、膝和鞋踝，以及不同上衣 / 裤子混搭的腰部接缝。

对长大衣、裙摆等资产，当前没有布料模拟或自动防穿插系统。应先用受控蒙皮适配所需动作；需要摆动骨、布料或专用动作时另行扩展，不能只靠文件夹投放获得这些功能。

## 6. 外星人颅冠、头型和配件

### 增加颅冠

在 `alien_design.py` 新增实体网格或从 Custom 导入，命名 `Hair_Alien_12`，加入 `made` 并使用共享 Head 骨。当前程序化循环是 `range(1,12)`，若沿用它需扩到包含 12。随后追加 `AlienHair` 名称，将 ID 12 加入一个 `AlienHairGroups` 子组。

颅冠需要有可见根部、实体厚度和明确轮廓，适配全部可选头型。总脚本按 `Hair_Alien_` 前缀生成 `AlienFit01–09`；它们来自 `alien_profiles` / `alien_fit()` 的缩放和偏移，只是统一适配规则，不能保证任意新形状都无穿插。逐个头型检查必要时要增加该颅冠的专用适配。

冠部 `Q_Skin / Q_SkinShade` 在运行时使用“颅冠基色”；`Q_Accent` 使用强调色，皮肤本体仍使用肤色。不要将所有冠部统一染成一个材质后再期待两个颜色控制都有效。

### 增加外星人头型

除模型和 `AlienFaces` 外，还需扩展 `alien_design.py` 的头型生成与 `alien_profiles`、`alien_specs`，主脚本的 `AlienFit` 生成范围，以及 `ToolCreatorOptions` 的 `AlienCrownWidth`、`CrownWidth()`、脸型上限与功能判断。运行时名称规则支持 `Head_Alien_10`，但目前这些范围仍只到 9，单独放入网格不足以启用新头型。

用标记的局部顶点组和各眼睛自己的锚点生成眼、眉、嗅觉器官、口器形态键。独眼、四目、鸟喙等头型不能套用人类五官位置。所有冠部也要增加该头型的 `AlienFit10` 适配；同时更新相关检查和截图循环。

### 增加面饰 / 身体装备

- 面饰走 `FaceAcc_Human_XX` / `FaceAcc_Alien_XX`，头部绑定及脸宽适配；装备走 `Gear_XX`，根据实际位置绑定 Chest、Torso、Hips 等原有骨骼。
- 同步 `FaceAccessories` / `GearAccessories`、`Normalize()` 的固定上限以及 QA 循环。没有对应物种网格时，应限制该物种的菜单选择，不能留下“选中但不显示”的选项。
- 当前外星人九种新解剖头型只允许面饰 ID 0 和 9；`FaceAccessoryIds()` 与 `Normalize()` 都有这个限制。要开放新眼镜，必须先完成各头型的贴合方案，再修改白名单；当前只有一个 `FaceAcc_Alien_XX` 名称，并没有自动按解剖头型切换不同眼镜网格的机制。
- 人类航行头盔 ID 11 会隐藏面饰；新增其他封闭头盔时，需要补充对应规则，而非改动 11 的旧含义。

## 7. 材质、贴图、颜色和动作

### 材质和贴图

| 现有材质名 | 运行时用途 |
| --- | --- |
| `Q_Skin`、`Q_SkinShade` | 肤色及暗部；外星人颅冠模块上会改用颅冠基色 |
| `Q_Hair`、`Q_Brow` | 人类发色 / 眉色，及沿用该语义的部件 |
| `Q_Eye` | 眼色 |
| `Q_Suit` | 服装主色 |
| `Q_Trim`、`Q_Accent` | 强调色 |
| `Q_Dark`、`Q_Ivory` | 现有固定深色 / 象牙色 |

优先使用这些语义和 `Astra/ToolV2/Character` Shader。材质按**名称**匹配目录，避免导入出 `Q_Hair.001`、`Material.001` 等名字后失去颜色控制。

确需新材质时，将 `.mat` 放在 `U/Materials/`，添加到 `U/Data/AvatarCatalog.asset` 的 `materials` 列表；若需要新的可编辑色槽，还要扩展外观数据、`ToolCharacterView` 映射和两端 UI。`CreateCatalog()` 对现有目录直接返回，运行 Initialize 也不会自动补齐它；应明确编辑目录或实现增量注册，保留现有资产引用。

当前 `U/Shaders/Character.shader` 使用颜色、分段光照和程序颗粒，**没有贴图采样或透明发片支持**。因此第三方的颜色贴图、法线贴图、透明头发卡片不会因拷贝文件就生效。可以将其重做为实体低模与材质分区；如决定扩展贴图管线，建议新增 `U/Textures/<资源名>/`，并同时实现 Shader 属性、采样和材质绑定。该 Textures 目录是建议，当前并不存在默认导入规则。

仅增加预设颜色，修改 `ToolCreatorOptions.cs` 的 `HumanSkin`、`AlienSkin`、`HairColors`、`SuitColors`、`EyeColors`、`AccentColors` 即可；外星人的颅冠色板目前复用 `AlienSkin`。颜色无需重新建模，但增加色块数量后须检查运行版调色面板的固定内容高度，避免新增行被截断。

### 动作资产

动画 FBX 放 `U/Animations/`，原下载包放 `Source/Downloads/`。必须使用有效 Humanoid Avatar，正确配置根位置 / 旋转与循环，再将实际 AnimationClip 加入 `AvatarCatalog.asset.clips`。

出现在策划动作菜单还需要注册 `U/Samples/Library.asset` 的 `actions`（ID 必须等于 Clip 名）；现有 `ToolV2Build.CreateSample()` 只定义 17 个常用动作，而底层目录有 42 个动作。只把 Clip 加进 Catalog 不等于增加了菜单。`ToolV2Import.Configure()` 当前仅明确处理已有模型列表和 `UAL1_Standard.fbx`，新增动画文件要单独配置或扩展导入逻辑。

不要靠改角色骨骼比例来解决新衣服或头发贴合问题；保留现有 Humanoid + Manual Playables 动作路线。只用现有动作时，新增普通服装 / 发型通常不需要修改 `ToolMotion.cs`。

## 8. 重建与发布

以下命令是之后实际增加资产时使用，本次整理文档没有执行模型重建。先保存 Unity 工作并关闭这个工程的 Editor，避免批处理打开同一工程。

```powershell
$toolRoot = 'F:\Documents\GitHub\GameDev_Performance_System\Tool\V2'

# 第一步：重新生成完整模型、Blend 与模块清单。
& 'F:\Blender\blender.exe' -b --python "$toolRoot\Tools\build_modular.py"
if ($LASTEXITCODE -ne 0) { throw 'Blender 构建失败；先检查输出。' }

# 第二步：Unity 导入变更、重建角色 Prefab、验证、导出包、构建 Windows 程序。
$editorArgs = '-batchmode -nographics -quit -projectPath "' + $toolRoot + '\UnityProject" -executeMethod ToolV2Build.BuildPlayer -logFile "' + $toolRoot + '\QA\asset-expansion-build.log"'
$buildProcess = Start-Process -FilePath 'F:\Unity\Installs\2022.3.62f1\Editor\Unity.exe' -ArgumentList $editorArgs -WindowStyle Hidden -PassThru -Wait
if ($buildProcess.ExitCode -ne 0) { throw 'Unity 构建失败；查看 asset-expansion-build.log。' }
Select-String -LiteralPath "$toolRoot\QA\asset-expansion-build.log" -Pattern 'TOOL_V2_VERIFY_OK|TOOL_BUILD_OK'
```

成功后主要结果：

- `U/Models/ModularCast.fbx`：包含新模块。
- `Source/Quaternius_Astra_Modular.blend`、`Source/modular_manifest.json`：最新模型源结果与清单。
- `U/Characters/Prefabs/`：按保存的角色配方重建。
- `Build/ASTRA Performance Tool V2.exe`：最新独立工作台。
- `Export/ASTRA_Performance_Tool_V2.unitypackage`：最新 Unity 资源包。
- `QA/tool-v2-verification.txt`、`QA/build-summary.txt`：验证和构建结果。

日常加资产使用 `BuildPlayer` 或 Unity 菜单 **Astra Performance Tool V2 → Build preview player**；只验证并导出包，可用 **Verify and export package**。

**不要把 `ToolV2Build.Initialize` 当成每次加资产的必需步骤。** 它还会重设示例演出树、示例单元、动作 / 场景配置等。沿用原 ModularCast 的导入设置和原材质时通常无需执行；新动画或新材质需要的是针对性注册。

模型和 Unity 资产的 `.meta` 要随项目一起保存，保持现有 GUID。新增资源使用新 `.meta`，不要复制别的资产 `.meta`；已有 FBX 的更新保留其 `.meta`。迁移到另一份工作副本时同时提交源文件、脚本、Unity 资产及对应 `.meta`。

`Tools/deliver_alien_update.ps1` 是本次历史更新的白名单同步脚本，路径固定指向当时的工作副本，**不是通用发布器**。后续直接在正式 Tool/V2 工作时不需要运行它，否则可能用旧工作副本覆盖新改动；确需同步时先更新来源路径与文件白名单。

## 9. 新资产验收清单与常见故障

### 每次至少检查这些项目

1. 模块清单存在正确对象名；ID 没有覆盖旧资产；两端菜单有显示名和正确子类别。
2. 新发型 / 颅冠：正面、左右侧、背面、俯视；脸宽最小 / 最大；不同脸型；发际线、耳部和冠部根连接。
3. 新衣服 / 装备：8 体型、身高 0.90 / 1.10；上衣裤子交叉搭配；待机、说话、坐下、维修、抬手等动作。
4. 无 NaN / 网格爆炸、缺半边、浮空部件、明显穿插；镜头旋转后角色和完整冠部仍在画面内，墙面不遮挡。
5. 调色作用在预期区域，材质使用 ASTRA Shader；保存、重新载入及 Prefab 实例化后外观一致。
6. 实际运行最新 Build，再检查 Unity 编辑器面板的分类、长标签、滚动范围和选中状态。保存本批截图到 `QA/AssetExpansion/<批次名>/`（建议新增目录）。

已有测试有边界：`ToolV2QA` 的发型遍历随选项长度变化，新增服装测试按服装数增长，但其他类别部分循环仍固定；`ToolHairRuntimeQA` 的发型列表是明确列举的，`ToolAlienRuntimeQA` 的头型 / 颅冠数量和原包发型列表也是固定的。新增 ID 后要扩展这些列表和联系表脚本，不能用旧截图数证明新资产已被覆盖。主脚本的短寸射线回归只验证 ID 10，不保证所有新短发都不露头皮。

| 现象 | 优先检查 |
| --- | --- |
| 文件放进去了，菜单没有新增 | 是否已合并到 ModularCast，并注册 `ToolCreatorOptions` 和对应分类 |
| 菜单有名字，模型不显示 | 导出对象名与 ID 是否一致；是否漏加 `made`；是否重新构建了 Player |
| 点击新衣服又变回旧衣服 | `Normalize()` 仍把 ID 限制在 0–9 |
| 新衣服显示，但裤子 / 鞋消失 | 当前共用 Outfits，新 ID 是否也有 `Legs_XX` / `Feet_XX` |
| 调色无效或材质不统一 | `Q_` 语义名、Catalog 材质引用及 `ToolCharacterView` 映射是否匹配 |
| 左右只剩一边 | Mirror 是否在添加形态键之前烘焙；当前 FBX 导出不临时应用修改器 |
| 发顶露皮或长发穿肩 | 头皮覆盖、源网格贴合及形态键；不要向下缩放整顶头发来制作短寸 |
| 新骨架使人物扭曲 / 手掌异常 | 是否重复引入骨架、单位变换错误，或重复执行手部 0.78 比例修正 |
| 新模型中的修改重建后消失 | 是否只改了生成 Blend / FBX，没有保存在 Custom 并接回构建脚本 |
| 原包自带贴图 / 透明头发没有效果 | 当前 Character Shader 不采样贴图、无透明发片路线 |
| CLI 构建通过但新增菜单有裁切 | 动态选项增多后是否检查两端布局、固定滚动高度和标签宽度 |

现有生成流程会对手网格及静止手指骨进行一次 0.78 修正。以生成 Blend 为参考制作带手部权重的衣袖 / 手套后，必须确认导入处于修正前还是修正后，避免二次缩小；发型和颅冠绑定 Head，不应改动这段骨架逻辑。

后续若频繁批量加资产，可再把编号、分组、兼容性和导入参数抽成数据目录，补自动扫描和缩略图注册。**本文记录的是当前脚本式接入方式，没有把这个后续方向当成已实现功能。**

服装本轮具体设计、源件映射和 QA 方法见 [太空服装扩充与调研](太空服装扩充与调研.md)。Git 克隆保留重建所需原始 Blend、使用到的 FBX、许可证及生成模型；Downloads 的压缩包和连续原始截图只保留本地，规则见仓库根目录 `Git追踪说明.md`。
