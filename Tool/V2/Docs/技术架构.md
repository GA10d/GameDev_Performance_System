# V2 技术架构

## 数据和职责

| 类型 | 职责 |
| --- | --- |
| `ToolAvatarCatalog` | 共享 ModularCast FBX、真实 UAL Clip、风格材质 |
| `ToolCharacter` | 物种、身份、来源、外观配方；不保存骨骼变换 |
| `ToolCharacterLook` | 模块编号、颜色、受限比例与形态键选择 |
| `ToolCharacterView` | 实例化骨架、模块显隐、BlendShape 权重、MaterialPropertyBlock |
| `ToolCharacterInstance` | Prefab 实例启动时恢复外观，防止属性块未序列化而丢色 |
| `ToolMotion` | 手动 PlayableGraph + 两路 AnimationMixer，Humanoid 动作采样与混合 |
| `ToolUnit / ToolGraph / ToolPackage` | 五轨数据、分支节点、资源初值 |
| `ToolPlayer` | 时间推进、人物生命周期、选择和资源结算 |
| `ToolV2CharacterCreatorWindow` | Unity 草稿编辑、分级选项、实时预览与保存 |
| `ToolWorkbench` | 可运行外观演示，使用同一建模与动画代码，JSON 外观保存 |
| `ToolV2CreatorBuild / ToolV2Build` | 目录初始化、资源绑定、预设、Prefab、Unity 包和 Player |
| `ToolV2QA / ToolRuntimeQA` | 结构检查、蒙皮采样、运行视图与截图 |

运行时代码只依赖 UnityEngine；Editor 文件放在 Editor 目录。V2 使用独立的命名空间、资源目录与 Shader 名称，避免与 V1 类型和资源 GUID 混用。不要把 V1 Character 资产直接拖入 V2 角色字段。

## Blender 管线

`Humans_Master_Humanoid.blend → Tools/build_modular.py → ModularCast.fbx → Unity Humanoid Avatar`

1. 复制原模块及蒙皮权重；人类头从 Casual_Head 保留 Skin / Eye / Eyebrows。
2. 外星人 0 号保留原灰裔头；1–9 号由 `alien_design.py` 生成独立解剖网格。头部与颅冠均绑定共享 Head 骨，运行时启用唯一头网格，颅冠通过 AlienFit 形态键适配。
3. 原作者发型 / 衣服保留源网格和骨骼组；新增发型、颅冠和配件在 Blender 绑定后导出。短寸和新发型的基础发帽从人类头皮网格裁切、外扩并收边，避免缩放后侵入头皮；旧圆弧长发已移除：`import_ubc_hair.py` 导入 Universal Base Characters 的五款头发，形成六个模块，保持源发束拓扑；其余发束、马尾与髻为有限面数的实体网格。不是运行时临时生成网格。
4. 人类脸型变形场以颈部为固定边界，同步用于头部、发型、面饰和纹样。外星人切换独立头网格，局部五官由建模时标记的顶点组和独立眼部锚点生成形态键，不套用灰裔眼睛位置。宽度微调和冠部适配共同作用，异形面饰能力由 ToolCreatorOptions 限制。
5. 体型是小幅顶点形变；整体身高在骨架外层等比缩放。禁止用非等比骨骼缩放捏脸。
6. 沿用 Demo/V2.1 手部修正：手网格及静止手指骨减为 78%；编辑前快照全部骨骼并断开连接，完成后只恢复端点吻合的连接；Thumb3 补为 Thumb3/4，保证 Humanoid 三节映射。
7. 导出形态键，保留骨骼层次。共享 51 根骨骼；各模块数据写入 JSON 清单。

原包腿部与鞋靴依赖 Mirror 修改器；必须在添加形态键前应用 Mirror。不能在 FBX 导出时关闭修改器却直接沿用原包的半边源网格。本版在 Blender 与 Unity 两侧都检查双侧几何。

可继续在 Blend 中修改，但生产改动应同步到生成脚本，否则重建会覆盖手工改动。新增模块必须带完整权重、保持连接边界、使用公共材质语义并增加选项与验证。

## Unity 导入与动作

`ToolV2Import` 采用 Demo/V2 的明确骨名映射。模型与动画均为 Humanoid；UAL 启用 Bake Axis Conversion，root 节点、根位置和旋转锁定；`_Loop` 片段设置循环。模型导入保留 BlendShapes、可读网格和 Transform，便于预览、验收及附件定位。

`ToolMotion` 以 Manual 更新 PlayableGraph。采样时设置 clip time，再 Evaluate(0)，根运动关闭，不用帧率累加重放所有历史。时间轴在动作开始的 0.22 秒从上一个相邻动作混入；不存在上一个动作时从 Idle 混入。随机拖动时混合权重由当前时间算出，因此可复现。播放对象禁用或销毁时释放 PlayableGraph。

坐下、下蹲等动作可能超出导入时的静态包围盒；SkinnedMeshRenderer 使用 updateWhenOffscreen，避免头部或衣服突然被剔除。角色预览和正式播放器复用相同的创建、外观和动作代码。

`ToolPortraitFraming` 根据当前启用的头 / 发型 / 面饰包围盒取景，按镜头方向投影八角点并考虑深度，防止高冠、横宽头型在旋转时裁切。捏人专用 ToolStage.Build(true) 将墙面放在完整环绕镜头之外；增加背面补光，正式演出继续使用原布景。`ToolPortraitBounds` 使用复用的 Mesh 和顶点列表，在手动 Playables 采样后 BakeMesh，避免读取滞后的 Renderer.bounds 导致坐下、跪下时镜头仍朝向旧位置；实例销毁时释放临时网格。`ToolBlocking` 只控制角色外层朝向，双人 / 过肩时让双方相向，不修改动画骨骼。时间轴预览实例化同一时间段的所有演员，与播放器使用相同的站位、采样及镜头函数。

## 保存与扩展

正式角色是 ScriptableObject + Prefab。保存前校验唯一 ID；修改现有角色从草稿复制回原资产，保留 GUID；新角色生成新资产。Prefab 保存模块显隐与形态键，ToolCharacterInstance 在 Awake 恢复属性块。共享材质不被角色染色操作污染。

独立程序的外观 JSON 含版本号、物种、显示名和外观配方，保存在 `Application.persistentDataPath/Characters`。本版提供最近文件载入；批量资产生产以 Unity 编辑器为准。

镜头、场景与表演数据保留独立类型。下一步如需语音口型、手持物或注视，应分别增加语音时间轨、交互接触数据与姿态修饰层；不要把它们写入脸型生成器，也不要修改原始动画曲线来补偿每个服装部件。

参考：[Unity BlendShapes](https://docs.unity3d.com/2022.3/Documentation/Manual/BlendShapes.html)、[Humanoid 重定向](https://docs.unity3d.com/2022.3/Documentation/Manual/Retargeting.html)。
