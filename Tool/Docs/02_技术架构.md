# 技术架构与扩展约定

## 数据资产

`ToolPackage` 引用 `ToolLibrary` 和 `ToolGraph`，并保存初始资源、耐心。`ToolLibrary` 管六名 `ToolCharacter`、`ToolAction`、`ToolCameraPreset`、`ToolScenePreset`。每段 `ToolUnit` 是独立 ScriptableObject，含人物、动作、台词、镜头、场景五类 Span；所有 Span 使用同一单元时间轴。`ToolGraphNode` 是 Unit、Condition、GlobalChoice、End 四种节点；出口用 slot 字符串匹配。选择文本使用相同 id，因此改名时需同步检查连线。

Unity 可序列化的每个 ScriptableObject、MonoBehaviour 都独立成与类名相同的 `.cs` 文件；不要把新组件随意合并进 `ToolData.cs`，否则场景/Prefab 的 `m_Script` 引用可能丢失。数据类和 `ToolValidation` 放在 Runtime，不依赖 UnityEditor，可在构建前与运行时共用。Editor 代码只负责编辑和导出，不承载播放逻辑。

## 实时播放顺序

`ToolPlayer` 从入口节点开始。遇到 Condition 立刻读资源并路由；遇到 Unit，按当前时刻先创建/移除角色，再取该时刻动作、场景和镜头，最后解析打字机文本或选择。`ToolMotion` 从 V3 FBX 的固定命名骨骼生成十七种姿态；四足的动态交给 V3 `CrawlerPerformance`。`ToolCameraMath` 将九种镜头公式计算为位置、注视点和视角；`ToolScreenFx` 应用信号效果。`ToolStage` 构造可重复的简化舱室，并按场景库更换墙面、地面和灯色。选择处理时先检查条件，再应用资源增减，只扣一次耐心，最后进入对应出口。

在 Unity 中，`ToolTimelineWindow` 通过 `PreviewRenderUtility` 显示角色和简化舞台；`ToolGraphWindow` 以 IMGUI + Handles 绘制节点与曲线。两个窗口直接编辑 ScriptableObject，并用 Undo/SetDirty 保存。点击“运行预览”进入真实 Game 视图；场景里的 `ToolPlayer` 不依赖 Editor 窗口。`ToolBuild` 负责示例资产生成、引用校验、打包与播放器构建。`ToolCapture` 只在播放器收到 `--tool-qa-dir=` 时运行截图，正常玩家运行不执行。

## 不变量与失效处理

- Actor Span 的 id 在单元中应稳定且唯一；动作 Span 必须被同 id 的 Actor Span 完整覆盖。
- 台词不得重叠或越界；Choice 是最后的台词，所有明文选项与沉默出口都连接。非 Choice 单元必须有 `next` 出口。
- Condition 节点有 yes/no；GlobalChoice 的每个选项有同名出口及 silence。未知资源按 0 处理；缺失出口会结束播放，导出前的校验应拦截。
- 角色模型与 V3 约定骨名 `Hips/Chest/Head/UpperArmL/UpperArmR/ForearmL/ForearmR`。批量换模必须先验证骨架，再验证预览的相机与字幕安全区。
- Scene/Camera Span 没覆盖时分别使用档案舱默认色与全景；引用未知的场景应被校验拒绝。

## 与主工程集成

工具工程和 Project-Astra `3D Demo/UnityProject` 都使用 Unity 2022.3.62f1 与 Built-in 渲染。`Export/ASTRA_Performance_Tool.unitypackage` 包括 `Assets/PerformanceTool` 及依赖的 V3 `Assets/Performance`。在主工程中导入后先检查材质与脚本编译，再打开 `Assets/PerformanceTool/Scenes/ToolPreview.unity` 运行；之后可以把 `ToolPlayer` 与自制相机放进现有场景，并将 `ToolPackage` 指向新的演出树。批量导入时勿覆盖主工程同名资源，先在分支或副本中验证。
